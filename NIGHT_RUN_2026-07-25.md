## ⚠️ Near-miss worth reading first

While applying the review's "stop stripping warnings" fix, I rewrote the harness's `normalize()`
filter and introduced an **unanchored regex**: ` *$` where the original had `^ *$`. Unanchored,
that matches *every* line, so `grep -v` deleted all output. The re-captured baseline came out
with **0 lines for 6 of 9 scripts**.

Had I committed it, every future `--check` would have compared empty against empty and **passed
forever**. The gate would have looked green while measuring nothing.

Caught only because the capture prints a line count per script and six of them read `(0 lines)`.

Two consequences:

1. **The instrument needs its own guard.** Adding one: refuse to write a baseline where any
   script yields zero result lines. Rules in code, not vigilance.
2. It is the same failure mode both reviews found in my work — building something that *looks*
   like it measures the thing while measuring a proxy, or nothing. Worth assuming the next
   instrument I build has this bug too until demonstrated otherwise.

The filter is fixed and tested against sample output before re-capture (results preserved,
boilerplate stripped, warnings collected into a sorted block).

## Problems to solve

### 1. 22 files cannot be verified by output diff

They read `/udd/reyle/`, `/proj/regeps/`, `/projects/talisman/` — unreachable from this machine,
so they cannot be run before *or* after, and phase 1's "diff its own outputs" check does not
apply.

**Proposed fix:** for a pure path change, verify *statically* — assert that the
config-resolved path string equals the old hardcoded literal. No execution needed, and it is
exactly the property phase 1 claims. Cheap to automate as a one-off test harness.

**Needs your call:** is a static equality check acceptable as the phase-1 gate for those 22, or
do you want them run on Channing before we trust them?

### 2. Three scripts are already broken on this machine

`05t_ref_cds_features.R:43`, `05u_paralog_annotation.R:41`, `build_paper_tables.R:25` all
`setwd()` into `…/results/isoform_transitions/Version_6.0/isopair_wrapper`, a directory that no
longer exists after the consolidation. There is no working "before" to diff against, so these
need the static check too — and a decision about whether `setwd` should survive the conversion
at all (config-resolved `setwd` is allowed by the linter, but these would be cleaner without).

### 3. The verification loop is slow (~15–20 min)

Fine as a gate, awkward as an iteration tool. If phase 1 converts script-by-script with a check
each, that dominates. Options: parallelise the nine scripts, add a per-script fast mode, or
batch conversions and check less often (weaker localisation).

### 4. Unconfirmed: `/proc/self/fd` in the path survey

Appeared in the absolute-path scan. Almost certainly a string inside a command, not a real
dependency, but I have not confirmed it.
